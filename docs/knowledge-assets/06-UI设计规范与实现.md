# 06 · UI 设计规范与实现（训练大屏）

> 对象：sunny-cx 训练中枢大屏（本地 `docs/train-console.html`）
> 来源：本项目 v2 → v18 共 **17 轮迭代**，每一轮都被用户判定「丑 / AI 味重」后重做。
> 全部结论均有**像素量化 / 无头 Chrome 实测**支撑。

---

## 一、核心认知：未来感不来自发光，来自秩序

### 三大「AI 指纹色」——出现即判定 AI 味
| ❌ 禁止 | 原因 |
|---|---|
| 青 on 暗（`#22d3ee`） | AI 生成 UI 第一大指纹 |
| 紫强调（`#a78bfa` / `#8b5cf6`） | 第二大指纹 |
| 蓝黑渐变（`#0f172a` 系） | 第三大指纹 |

### 其他硬禁止
点+连线的"网络图"（太单薄）· 满屏霓虹/光晕 · 圆角卡片+发光大数字 ·
渐变文字 · 装饰性玻璃模糊 · 星空撒点 · 大量留白 + 一坨中心图形 ·
**Inter / Roboto / Arial**

### 必须做
- 底色**中性灰黑** `#0a0a0b`（**不是蓝黑渐变**）
- 界面由**细线**构成（线宽 ≤ 1px）——层次感来自抗锯齿灰阶，不是发光
- 一屏 **1 个视觉锚点**，其余退后
- **强调色 ≤ 2 种**；红色一屏 ≤ 2 次且只做告警
- 面板间用 **1px 线**分隔（不是卡片）
- **每个发光元素都要能说出它对应哪个真实指标**
- `prefers-reduced-motion` 降级

## 四、★ 信息优先级（本项目最重要的一条规范）

> **主视觉的信息优先级：仪器读数 > 结构骨架 > 动态纹理。**

**三者顺序颠倒（把"动态纹理"做成主角）→ 就会出现"很炫但读不出内容"。**

### 具体判据
- **主视觉里必须能一眼数出"层"；数不出的纹理 = 噪声。**
- 把 8 行读数挤进 3 列 → 每个元素都对，整体读不出 →
  这不是审美问题，是**结构问题**。
- 解法只有一条：**一个面板只承担一个职责。**

### 实战踩坑（走弯路记录）
本项目曾连续多轮**在"调纤维形态"上打转**（海胆→乱麻→唱片→月牙，共 5 版），
方向本身就偏了 —— 因为资料库讲的是「**弧带承载数据**」：
沿弧线排布垂直短条块（像磁带/条形码），**条块高度编码数值**。
**主视觉的重心应该是"环 + 刻度条"，纤维只是背景纹理。**

## 五、环形纤维穹顶 · 可复现参数

| 参数 | 取值 | 为什么 |
|---|---|---|
| 纤维总数 | **520 条**（长纤维）+ 层间短纤维 | <300 显单薄；>900 糊成一团 |
| 长纤维跨层 | 跨 **2~4 层** | 跨太多 = 直线贯穿、丢层次 |
| 层间短纤维 | 每层每节点 6 条 | 填充层间密度，制造"束"感 |
| 弯曲量 `bend` | `(rand-0.5)×0.028` | **必须 ≤0.05**，超过退化成"蚊香漩涡" |
| 角度散开 `spread` | `(rand-0.5)×0.05` | 产生"束"的厚度 |
| 基础透明度 | **0.050 ~ 0.160** | 灰阶层次的来源；统一值 = 平 |
| 呼吸相位 | 随机 0~2π | 每条明暗独立变化 → 画面"活" |

### 极坐标几何（非对称是关键）
```
CX = W * 0.33      ← 不是 0.5！环靠左，右侧留给光轨流
CY = H * 0.50
R  = min(W*0.27, H*0.40)
layerR(i) = R * (0.16 + 0.84 * i/(N-1))
```

### ★ 纤维/流线的三条硬约束（本项目踩了 5 版才总结出）
1. **角向跨度必须与径向跨度同比**，否则是**辐条**不是束
2. **不能只用"内层→外层"连**，否则全部穿心成**乱麻**
3. **半径完全不变 = 唱片**，必须叠加缓慢半径漂移（螺旋）才有交织

> **三者只能同时满足才出"束"。**
> 补充：二次贝塞尔在 60°+ 会明显偏离圆周、切进层环之间 → 角向跨度 >0.30rad 时**
> **改用三次贝塞尔。**

## 六、色彩与排版规范

### 色彩（实测值）
| 用途 | 颜色 |
|---|---|
| 底色 | `#0a0a0b` |
| 主色（细线/文字主体） | `#e8e8ea` |
| 次级文字 | `#8b8b92` |
| 三级文字 | `#4e4e54` |
| 强调 1（激活/正常） | `#4ade80`（绿） |
| 告警（过拟合/异常） | `#ef4444`（红，一屏 ≤2 次） |
| 线透明度分层 | 0.04 / 0.08 / 0.13 / 0.26 —— **用透明度产生层级，不用不同颜色** |

### 排版
| 层级 | 字体 | 字号 | 字距 |
|---|---|---|---|
| 主标题 | 压缩无衬线大写 | 13~15px | .18em |
| 面板标题 | 等宽大写 | 10px | .20em |
| 数据读数 | 等宽 | 11~12px | tabular-nums |
| 大数字 | 等宽 | 30~38px | -.02em |
| 注释 | 等宽 | 9~10px | .10em |

### ★ 绿色的语义化（不是装饰）
```js
act > 阈值  →  rgba(74,222,128, α)   // 绿：该纤维"正在激活"（真实语义）
否则        →  rgba(232,232,234, α)  // 近白：静息
```

### ★ 稀缺性判据必须用「全局分位」，不能用固定阈值
三次踩坑记录：
| 判据 | 结果 |
|---|---|
| `act > 0.92` | ❌ 深层成片绿（激活幅值随深度单调增） |
| `act > 0.985` | ❌ 32 层里十几层均值都逼近全局最大，仍成片 |
| **全局 97.5 百分位** | ✅ 绿色数量恒定约 2.5%，**不随层数增长** |

> **规律**：凡是"随深度单调增"的量做稀缺性判据**必然失效**，
> 必须用全局分位。

## 七、动画规范（消除"拼接感"）

### 动效覆盖面积比幅度更重要
- ❌ 单列扫描（覆盖 1/20）→ 帧间差分 0.28 → 像死了
- ✅ 逐行滚动带（覆盖 15%）→ 差分提升 4 倍

> **要动就动一片，不要动一条线。**

### 消除"像图片拼接"的四条根因
| 根因 | 修法 |
|---|---|
| 硬切无转场 | 段间**交叉溶解 0.55s**（smoothstep） |
| 大屏帧在倒放 | 全面**单向播放**（曾用 `reverse` 做乒乓，观感极假） |
| 字幕整句闪十几秒 | 按标点切小句 + **逐词高亮** |
| 画面全程静止 | **常驻微动** + 逐帧进度驱动 |

### ★ 量化判据：相邻 1s 采样差
- 修复前：入场动画 2~3s 跑完，之后 **75% 时间画面完全静止（差值恒 0.00）** ← 拼接感真正根源
- 修复后：**0.044~0.17**，全片 18 个抽帧点**无一静止**

### 帧间差分验收（实测）
| 区域 | 差分值 | 判定 |
|---|---|---|
| 主视觉 | 8~17 | 有动 |
| 波形 | 228 | 活跃 |
| loss | 25.6 | 活跃 |
| 矩阵 | 1.19 | 有动（但偏低） |

> 标准：**各区域同量级，无 < 1/5 的静区**。

## 八、验收清单（逐条机器可判定）

| 检查 | 判定方式 | 通过标准 |
|---|---|---|
| 无 JS 异常 | `window.__errs__` | 长度 = 0 |
| AI 指纹色 | grep `22d3ee\|a78bfa\|8b5cf6\|0f172a` | **0 次** |
| 圆角/阴影/玻璃模糊 | grep | **0 次** |
| **彩色占比** | 按 alpha 合成到黑底后统计 | **< 1%** |
| 强调色种类 | 统计 `#` 色值 | ≤ 2 + 1 告警 |
| 截图体积 | 文件字节数 | 空白期骤降 **10 倍**（42KB vs 400KB）→ 预警 |
| 无大块静止 | 各画布帧间亮度差分 | 各区域同量级 |
| `prefers-reduced-motion` | 代码检查 | 有降级 |
| 大屏布局 | 目视 | 上方 ≈60%，下方 ≈40% |

> ⚠ **彩色统计必须按 alpha 合成到黑底再判**：
> ```js
> var a = px[i+3]/255;
> var lum = (0.299*px[i]+0.587*px[i+1]+0.114*px[i+2]) * a;   // ← 必须乘 alpha
> ```
> 否则会把 `rgba(232,232,234,0.05)` 这种"几乎看不见的笔画"算成亮白像素 → 假高占比。

## 九、★ 排障优先顺序（画布异常时照此走）

### 第一步永远是：捕获 `window.error`，不是盯绘制代码

本项目**最致命**的实现陷阱：
```js
// "use strict" 下引用未声明变量 → ReferenceError
render();                          // ← 崩在这里
requestAnimationFrame(loop);       // ← 这行永远不执行
```
**`render()` 在 `requestAnimationFrame` 之前调用 → 一崩，渲染循环永不启动
→ 整块画布全黑且无任何报错。**

### 正确排查顺序
```
怀疑画布坏了
  ├─ ① 页面内 getImageData 有像素吗？
  │     否 → 真的没画 → 查 __errs__ 行号 / 绘制条件分支
  │     是 → 往下
  ├─ ② __errs__ 为空、循环在跑（两帧内容有变化）？
  │     是 → 代码是活的
  ├─ ③ 截图是 --disable-gpu 拍的吗？
  │     是 → 换默认参数重拍 → 现象消失 → 假故障，别改代码
  └─ ④ 亮度确实远低于参照物？→ 真问题，按参照数据调
```

### 备用判据：截图文件体积
**空白期会骤降 ~4~10 倍**（42KB vs 400KB）。比肉眼看图快 10 倍、更客观。

## 十、五个具体实现坑（全部已实测复现）

### 坑 1：`--disable-gpu` 让 canvas 在截图里"消失"
- 现象：截图核心区全黑，但页面内 `getImageData` 显示 15.3% 非透明像素
- 根因：软件光栅化路径**不把 Canvas2D 图层合成进 `--screenshot`**
- 修：**无头截图必须去掉 `--disable-gpu`**
- 实测：`--disable-gpu` 亮像素 0.56% vs 默认 **8.63%**

### 坑 2：给 canvas 设 `style.width/height` → 画布永久锁死
- 现象：曲线只画到容器宽度约 62%
- 根因：inline style 优先级最高，首次测量值（CSS Grid 列宽稳定前）被永久锁定
- 修：**绝不**设 `style.width/height`；只设后备缓冲区尺寸；
  用 **`ResizeObserver`**（不是 `window.resize`，网格列宽变化不一定触发它）；
  尺寸未变时**不重设** `canvas.width`（重设会清空画布 → 闪烁）

### 坑 3：`setTimeout` 探针被无限 rAF 循环饿死
- 修：探针**放进 rAF 循环内部**，用帧计数触发
  ```js
  window.__FR = (window.__FR||0)+1;
  if(window.__FR===40 || window.__FR===200){ document.title = probe(); }
  ```

### 坑 4：改注释块匹配到旧块头 → 注释断裂 → 整页 SyntaxError
- 现象：截图 42KB（正常 400KB），全黑
- 判据：`__errs__` 能给出**精确行号**
- 注意：SyntaxError 发生在 IIFE 解析期，`safeRender` 的 try/catch **拦不住**

### 坑 5：mock 数据自己不自洽 → 验真时被误导
- 现象：台账显示 `val 13.4466 BEST` 而当前 loss 只有 7.03
- 根因：mock 的 history 用一条公式，`state.loss` 却是硬编码
- 教训：**验收工具的失真，比被测代码的 bug 更浪费时间** —— 会让你去修一个不存在的问题

## 十一、一句话总结

> **规范负责"不丑"，参数负责"好看"，异常处理负责"能看到"，信息层级负责"读得出"。**
> 四者缺一：只有规范 → 默认值填满、仍 AI 味；
> 只有参数 → 好看但一崩全黑；
> 没有异常处理 → 连自己哪里丑都不知道；
> 没有信息层级 → 每个元素都对，但整体读不出。
