# 11 白话问诊的正确性架构与实测

> 目标：用户用**白话**说哪里不舒服，系统给出中医辨证 + 参考方剂 + 出处。
> **前提是"正确"，而不是"像人话"。**
> 本文只收真机实测数据；所有未验证项均标注。

## 一、为什么不能靠 0.5B 自由生成

`sunny-cx` 是 524M 参数、2,043 本古籍、1.08 亿 token 预训练的**纯语言模型**。
它在自由生成里作答，会出现三类**无法靠提示词消除**的硬错误：

| 错误类型 | 机制 | 例子 |
|---|---|---|
| 证型乱判 | 交叉熵目标只对齐"下一个 token"，不对齐医学因果 | 「乏力 + 舌紫暗」被判成阴虚火旺 |
| 方名臆造 | 模型会按"XX汤"的构词法造出不存在的方 | 益气活血通脉汤 |
| 药味/剂量幻觉 | 组成与剂量是高熵槽位，最容易被"编得像" | 往四妙丸里加天山雪莲；「苍术9克」 |

3.8995 的 val loss 是**语言建模交叉熵**，与辨证准确率没有函数关系。
所以结论很硬：**正确性不能来自模型，只能来自架构——不给它说错的机会。**

## 二、「正确」在工程上必须可检查

把"正确"拆成 7 个可判定项，前 6 项由架构保证，第 7 项靠评测集实测：

| # | 指标 | 要求 | 谁保证 |
|---|---|---|---|
| 1 | 证型 ∈ 35 类 | 100% | 打分器只在表内排序 |
| 2 | 方剂与证型一致 | 100% | 查表，不生成 |
| 3 | 药味 ∈ 该方组成 | 100% | 组成字段直出 |
| 4 | 不出现剂量 | 100% | 词表层禁用（正则 + 组成断言） |
| 5 | 不出现绝对化断言 | 100% | `check_answer` R5 |
| 6 | 必有免责声明 | 100% | `check_answer` R6 |
| 7 | 证型 top-1 准确率 | 评测集实测 | 见第五节 |

## 三、六层架构

```
白话主诉
  ↓ ① 规范化  受控词表 70 症状 / 321 别名 → 规范症状
  ↓ ② 证据    规范症状 → (病位|病性) 轴证据权重
  ↓ ③ 判定    35 证型按轴覆盖率打分（不做生成）
  ↓ ④ 查表    只读 syndrome_table.json：治法/方/组成/出处
  ↓ ⑤ 渲染    模板化白话，槽位全部来自 ③④
  ↓ ⑥ 闸门    check_answer() 七条规则；不通过则退安全模板
  ↓ ⑦ 输出 / 拒答
```

**模型（若接入）只允许改写 ⑥ 已通过校验文本的措辞，不得引入任何新的证型名、
方名、药味。** 这是"正确"唯一能兑现的形态。

## 四、受控词表与轴模型

### 4·1 轴从证型表自动解析，不手写

`syndrome_table.json` 的 `base` 字段形如 `全身·气虚+血瘀`，用它自动拆出
病位轴与病性轴，**避免"手写类别表 ↔ 数据表"静默错配**：

```python
left, _, right = base.partition("·")
pos = [left]; nat = right.split("+")
```

启动时双向断言：词表的轴 token 必须都在证型表里，证型表的 token 必须都在词表轴里，
**任一不匹配直接 `SystemExit`**，不给静默失效的机会。

### 4·2 「全身」不设约束（实测踩过）

最初把「全身」当成必填病位，结果 **全身性证型永远压在 100% 以下**：
主诉说不出"我全身"，阴虚火旺（全身·阴虚）覆盖率恒为 62.5% → 全部降级为 weak。
改为：`pos = [t for t in pos if t != "全身"]`。这是"约束模型"而不是"放宽标准"。

### 4·3 单 token 贡献封顶（实测踩过）

第一版 `got += min(TOKEN_CAP, ev)` 导致覆盖率能到 **150%**——
反复描述同一个症状就能把某证型刷到第一。改为 `min(该 token 标称权重, 证据和)`，
覆盖率恒 ≤ 100%。

### 4·4 单字别名会误伤（实测踩过）

「水肿」原本带别名 `肿`，于是「手指关节肿起来了」被判成 **阳虚水泛证**——
这是留出集实测抓到的，属于**会给出错误结论**的危险 bug。
单字/双字泛化别名一律不进入词表。

## 五、判定阈值与降级（宁可拒答，不可错答）

| 条件 | 决策 | 行为 |
|---|---|---|
| 无任何症状命中 | `refuse` | 列出需补充的问诊要点 |
| 最高分 = 0（全零） | `refuse` | **不显示候选**（全零时 ranked[0] 只是字母序第一，展示它等于凭空造结论） |
| 覆盖率 < 50% 或无病性证据 | `refuse` | 不判 |
| 覆盖率 50%~75% | `weak` | 只给方向 + 明确列出**缺哪些要素** |
| 覆盖率 ≥ 75% 且前二差 ≥ 0.04 | `ok` | 给证型 + 方剂 + 出处 |
| 覆盖率 ≥ 75% 但前二差 < 0.04 | `differential` | 给鉴别，明确"请勿自行选方" |

## 六、闸门规则与负样本实测

| 规则 | 检查内容 |
|---|---|
| R1 | 出现「XX证」但不在 35 类内 → 拦 |
| R2 | 出现「XX汤/丸/散/饮/煎/丹」但不在表内 → 拦 |
| R3 | 【参考药味】段里出现任何方剂组成外的药味 → 拦 |
| R4 | 出现剂量（克/钱/两/ml/mg/适量/少许）→ 拦 |
| R5 | 出现绝对化断言（确诊/一定是/根治/100%）→ 拦 |
| R6 | 缺免责声明 → 拦 |
| R7 | 【参考方剂】/【备选方】段内**没有任何**可核验方名 → 拦（正向断言，黑名单挡不住"把治法写进方剂位"） |

**编者注的例外必须收窄**：证型表的 `note` 是人写的编者注，会提到表外方名
（如「湿重用三仁汤」）。这些**只允许出现在【用药要点·编者注】段内**，
挪到别处一律算越界——否则模型可以把编造的方名塞进注段蒙混过关。

### 6·1 负样本实测（8/8 全拦，0 漏检）

| 注入的错误 | 拦截依据 |
|---|---|
| 编造方名「益气活血通脉汤」 | 方名不在表内 |
| 编造药味「天山雪莲」 | 药味不在任何方剂组成内 |
| 编造证型「肝郁脾虚湿阻证」 | 证型名不在 35 类内 |
| 给出剂量「苍术9克」 | 出现剂量表述 |
| 绝对化「确诊为前列腺炎」 | 出现绝对化断言 |
| 删掉免责声明 | 缺少免责声明 |
| **表外真方「当归四逆汤」** | 方名不在表内（比编造更危险，人看不出错） |
| 治法冒充方名「疏风散寒解表」 | R7 结论位无可核验方名 |

## 七、实测数据（2026-10-18，18 + 12 条）

| 口径 | 样本 | top-1 | top-3 | 判错且给结论 |
|---|---|---|---|---|
| 调参集 `golden_set.jsonl` | 18 | **88.9%** | 88.9% | **0** |
| **留出集 `holdout_set.jsonl`** | 12 | **16.7%** | 25.0% | **0**（修复「肿」后） |

**必须这样报数**：调参集的词表是照着它调的，88.9% 只是**上限**，不是泛化能力。
留出集 16.7% 才是第一次诚实测量。

### 7·1 16.7% 的根因：不是判定逻辑错，是白话召回不足

留出集 12 条里 8 条失败，逐条看下来全部是**症状没被识别**，不是打分错：

| 用例 | 用户说法 | 词表里的说法 | 结果 |
|---|---|---|---|
| H04 | 半夜老醒 / 手心脚心**发烫** / 被子都汗湿了 | 多梦易醒 / 手心脚心**发热** / 夜里出汗 | 未命中 |
| H02 | 下身总是**潮乎乎**的 / 腿像**灌了铅** | 阴部潮湿 / 下肢沉重 | 未命中 |
| H08 | 关节肿起来了 / **弯不了** | 关节肿大变形 / **弯不下去** | 未命中 |
| H10 | 吃点凉的就加重 / **手脚凉** | 喜温喜按 / **手脚冰凉** | 未命中 |

结论：**别名是"教材说法"，不是"人的说法"。** 判定引擎本身是安全的
（失败一律降级为 refuse/weak，不给错误结论），但可用性差。

## 八、已知缺陷与下一步（按优先级）

1. **白话召回**（P0）：别名 321 条远不够。需要真实用户语句或模型产出的口语表达
   做扩充；**不许用留出集来调**，调一次就换一份新的留出集。
2. **复合证型**（P1）：单 token 模型无法表达「气虚 + 血虚 → 气血两虚」的合取，
   气血亏虚/气阴两虚覆盖率天然偏低，会降级为 weak（安全但不好用）。
   解法是加合取规则，而不是继续加别名。
3. **证型表只覆盖 89.1% 医案**：另 10.9% 的证型不在 35 类内，用户说到了也判不出，
   只能拒答。这是覆盖度问题，不是正确性问题。

## 九、架构结论：模型该做哪一层

这是本轮最重要的一条判断：

> **不要 0.5B 做「辨证下结论」，让它做「白话 → 规范症状」的受限归一化。**

- L1 归一化：模型擅长（同义改写、口语理解），且输出可被**受控词表 + 校验**约束住
  （只能输出词表内的症状名），错了也只是召回问题
- L3 结论：必须由打分 + 查表给出，模型参与就等于把正确性交给概率

这也解释了为什么 SFT 白话语料该建成「白话主诉 → 规范症状列表」，
而不是「白话主诉 → 证型 + 方剂」——后者会把幻觉直接写进监督信号。

## 十、复现

```bash
# 单条判定
PYTHONPATH=sunny-cx/src python -m sunnycx.consult \
  --text "我最近老觉得累，一动就出汗，舌头发紫，身上老是一个地方刺痛"

# 对任意文本（含模型输出）做越界校验
PYTHONPATH=sunny-cx/src python -m sunnycx.consult --check answer.txt

# 全量自检：A 调参集 / A2 留出集 / B 闸门 8 条 / C 表内一致
python sunny-cx/scripts/selfcheck_consult.py
```

产物：

| 文件 | 作用 |
|---|---|
| `sunny-cx/data/consult/symptom_lexicon.json` | 受控词表（70 症状 / 321 别名 / 轴定义） |
| `sunny-cx/data/consult/golden_set.jsonl` | 调参集 18 条 |
| `sunny-cx/data/consult/holdout_set.jsonl` | 留出集 12 条（**已被读过，下次调完要换新的**） |
| `sunny-cx/src/sunnycx/consult.py` | 六层引擎 + `check_answer()` |
| `sunny-cx/scripts/selfcheck_consult.py` | 可回归自检 |
